# Sync Policy — Protection Rules

## Automatic protection (never overwrite on sync)

1. **Local-only** — skill directory exists in project but not in upstream `.agents/skills/`.
2. **project-local origin** — `metadata.origin: project-local` in SKILL.md. `universal-skill-creator` writes it; `agent-loom-sync --apply` stamps it on local-only skills missing it.
3. **forked_skills** — key listed in `.agents/agent-loom-sync.json` with optional reason string.
4. **protected_skills** — explicit list in config (manual pins).

## Safe to update (rsync from upstream)

- Skill exists in both repos
- Not protected by any rule above
- Directory hash differs from upstream

## Add (new upstream skills)

- Present in upstream, absent locally → full directory rsync in.

## Unchanged

- Hash match — skip rsync.

## Resolving forks

When user wants upstream version of a forked skill:
1. Remove from `forked_skills` and `origin: project-local` if set
2. Back up local copy: `mv .agents/skills/<name> .agents/skills/.backup-<name>-<date>/`
3. Re-run sync with `--apply`

When user wants to keep fork permanently:
- Add to `forked_skills`, or rely on auto-stamp if the skill is local-only (not in upstream)

## What is NOT synced by default

| Path | Reason |
|------|--------|
| Project root `AGENTS.md` | Generated by project-setup for this repo |
| `docs/` in project | Project artifacts |
| Whole `.agents/` delete | Would remove local skills |

Optional with user consent: `.agents/ROUTING.md` if unchanged locally.
