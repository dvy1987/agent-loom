# UX Context Checklist (pre-direction)

Capture what is known before generating directions. Missing items do not block
exploration — note gaps in DIRECTION.md under `## Context gaps`.

## Research (what do we know about users?)

- [ ] Target audience named with specificity (not "everyone")
- [ ] Problem validated or hypothesized with evidence level noted
- [ ] Competitive landscape: 2–3 reference products and what they get right/wrong
- [ ] User feedback or research artifacts referenced (if any)

## Plan (what is the job?)

- [ ] Primary user job-to-be-done stated in one sentence
- [ ] Critical user flows identified (max 3 for MVP)
- [ ] Success metric or outcome defined (even if approximate)

## Constraints (what bounds the design?)

- [ ] Technical stack or platform constraints
- [ ] Brand assets or existing design language to respect or break
- [ ] Accessibility or compliance requirements
- [ ] Timeline/MVP scope that limits exploration depth

## How to use

In Step 1, extract answers from `docs/product-soul.md`, PRD, specs. For any unchecked
item with no source, ask ONE bundled question if gaps would mislead direction choice:
"Who is this for, what job does it do, and which 2 products should it feel closest to
(or farthest from)?" Record unchecked items as context gaps — do not stall exploration.
