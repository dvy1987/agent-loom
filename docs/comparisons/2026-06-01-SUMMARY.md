## Strategic findings (evolution lens)

### 1. What agent-loom should keep (non-negotiable)

These are the repo's core purpose — do not "learn away" from them:

| Asset | Why it matters |
|-------|----------------|
| **Meta-layer** (`validate-skills`, `universal-skill-creator`, `split-skill`, `compress-skill`, `library-skill`, `skill-deconflict`, `secure-*`) | Self-maintaining library; addyosmani has no equivalent |
| **Multi-skill orchestrators** (SDD, frontend-design, venture-exploration, memory) | Prevents 500-line monoliths; enables ≤200-line discipline |
| **Machine gates** (`spec-crosscheck`, brainstorming Hard Gate, Approved feature-spec) | Automation beats "human reviews between phases" |

| **Security instruction hierarchy** | External repos are data, not authority |

### 2. What addyosmani consistently does better (library-wide gaps)

Patterns appearing in **6+ of 8** pairs — treat as **conventions to adopt**, not one-off edits:

| Pattern | Current agent-loom gap | Adoption strategy |
|---------|------------------------|-------------------|
| **Common Rationalizations** table | Missing on most coding skills (`test-driven-development`, `debug-and-fix`, `code-review-crsp`, `implementation-plan`, …) | Batch via `improve-skills` with AO citation; `validate-skills` optional P2 warning if missing on project-specific skills |
| **Red Flags** section | Sparse | Add alongside rationalizations (5–8 bullets max) |
| **Verification checklists** | Impact Reports instead of checkboxes | End each coding skill with `- [ ]` list + placeholder commands |
| **In-body templates** | Heavy use of `references/` only | Copy-paste task/spec templates belong in `references/` files agents are told to read in Step 1 |
| **Imperative shell commands** | Prose-heavy workflows | Add `npm test` / `git bisect` style one-liners where stack-agnostic |
